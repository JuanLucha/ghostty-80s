# Platform switches are compile-time, not detected

The shader must produce the same look on both of Ghostty's rendering backends, and they differ in exactly two ways that reach a custom shader: Metal hands over colour per `alpha-blending` with a y-down fragment coordinate, while OpenGL on Linux pairs different defaults with a y-up coordinate. Both differences are expressed as `const` switches, `BLENDING_NATIVE` and `Y_DOWN`, because neither can be recovered at runtime without damage. The colour space cannot be detected, since the same encoded numbers describe P3 and sRGB, and inferring which one the compositor used means guessing at pixel contents, which goes wrong on gradients, flat fields and saturated primaries alike. The y direction could be found by mirroring the pane, but that perturbs the very frame being measured and needs a second sample of every effect. Explicit switches keep the shipped macOS output unchanged apart from pow round-off, cost nothing at runtime, and reduce the Linux setup to a two-line edit whose failure mode is documented in the README rather than hidden inside a heuristic.
